# Mischief of Agents reference

How every part of Mischief of Agents (`misag`) behaves. For an overview, building and running, see the [README](../README.md).

## Usage

| Action | How |
| --- | --- |
| New terminal tab (in the active tab's directory, or `$HOME`) | Click the terminal icon at the top right |
| New terminal or Claude tab with a name and directory | Shift+click the terminal icon |
| New Claude tab in a folder | Hover the folder (or the workspace folder at the top) in the Workspace box and click its Claude icon |
| Rename a tab | Double-click it |
| Close a tab | Click ✕ or middle-click the tab |
| Reorder tabs | Drag a tab along the tab bar; Settings, Workspace, Flows and flow editor tabs stay after the terminal tabs |
| Restart a tab whose process exited or failed to start | Press Enter in it |
| Paste the selection | Middle-click a terminal: it pastes what is selected anywhere on the desktop (the primary selection), bracketed if the program asked for it. A program that tracks the mouse (tmux, vim) gets the click instead; Shift+middle-click pastes there. misag reads it through GTK itself, as WebKitGTK 2.54 crashes the app pasting a middle click on its own |
| Copy the selection | Select text in a terminal (Shift+drag where a program tracks the mouse), then press Ctrl+Shift+C or right-click it |
| Paste the clipboard | Right-click a terminal with nothing selected: it pastes what was copied (the clipboard), bracketed if the program asked for it, in place of WebKit's menu, which has no Paste there. A program that tracks the mouse gets the click instead; Shift+right-click pastes there. A failed read shows a notice |
| What a paste types | Line breaks are sent as Enter and other control characters are dropped, for middle-click and right-click pastes alike. To a program that did not ask for bracketed paste (a plain shell), text of more than one line runs line by line, so misag asks before pasting it |
| Open a link | Ctrl+click a link a program marks as one (OSC 8 hyperlinks, as Claude Code and `ls --hyperlink` print); it opens in the system browser. Plain URLs in the output are not clickable |
| Toggle the sidebar | Burger button at the left of the tab bar |
| Resize the sidebar | Drag its right edge (160 to 600 px, leaving the terminals at least 320 px), or press Left, Right, Home or End on it; double-click it, or use Reset sidebar on the Settings tab, for the default 240 px |
| Reorder the sidebar's toolboxes | Drag a toolbox by its header, or press Alt+Up or Alt+Down on it; Reset sidebar on the Settings tab puts them back |
| Browse your workspace | Workspace box in the sidebar: click a folder to open it; the reload button refreshes it; the gear opens the Workspace settings tab |
| Change the workspace folder | On the Workspace settings tab, click the path to pick a folder; the house button goes back to your home directory |
| Type a file's path into the active tab | Click the file in the Workspace box (the tab must be running) |
| Manage flows | Flows box in the sidebar: its gear opens the Flows tab, to add, rename, reorder, archive and delete flows |
| Export or import a flow | On the Flows tab: a flow's download button saves it as a JSON file; Import… adds one. Or from a terminal: `misag flow export`, `misag flow import` (see `misag flow help`) |
| Have Claude write a flow | Ask Claude in a misag tab: "run `misag flow help`, then add a misag flow that …". The help tells it the file format, and the flow shows up in the Flows box |
| Edit a flow's steps | Click the flow in the Flows box, or its pencil on the Flows tab; it opens the flow's editor tab |
| Run a flow | Select a Claude tab (or a terminal tab running `claude`), hover the flow in the Flows box and click ▶ |
| Stop a run | With its tab selected, click ■ in place of its flow's ▶ in the Flows box; closing its tab stops it too |
| Answer a waiting run | With its tab selected, use the Flows box: ▶ beside ■ for a Manual step with one output, or the output buttons under its flow for several. Or click the flow and pick in the editor's run bar, where Continue (⏭) also has Claude go on with a step that needs attention |
| Resume an earlier Claude conversation | Session history box in the sidebar: click a session to resume it in a new Claude tab in its folder; its pin button keeps it at the top |
| Settings | Click Settings at the bottom of the sidebar; it opens a Settings tab |

## Behaviour

- Tabs have a kind. Claude tabs run Claude Code. Terminal tabs run a login shell (`$SHELL -l`, or `$SHELL -lc '<command>'` for a saved command). A leading `~` in the directory is expanded.
- A tab is labelled with the folder its process is in (`~` for your home directory), checked every 2 seconds so it follows `cd`; a tab you renamed keeps its name. The tooltip shows the terminal's title and the full directory. The icon is Claude's for a Claude tab, and for a terminal tab while Claude runs in it, and a terminal otherwise. While Claude is working, a spinning loader takes the icon's place, read from the spinner Claude puts at the start of the terminal title.
- A `claude` you start at a terminal tab's shell prompt is remembered too. Terminal tabs get `MISAG_TAB`, `MISAG_DB`, `MISAG_WRAPPER`, `MISAG_CLI` and a `PATH` that starts with `<data dir>/bin`, where misag writes a `claude` wrapper at every start (changes to it are lost), then `<data dir>/cli`, which holds a `misag` that runs this misag (Claude tabs get `MISAG_CLI` and that directory too; both only with a usable database). The wrapper takes only its own directory off `PATH`, so Claude finds that `misag`. The wrapper runs `misag --claude-launch`, which starts the real `claude` like a Claude tab: with the current settings (see the Settings tab below) and the same session hook, which also records Claude's pid; hook failures go to the same `hook.log`. Your own arguments come last. Without a usable database it starts Claude cautiously and untracked; if the misag binary the wrapper points at has gone, the wrapper says so and runs `claude` unchanged. Every 2 seconds, and when the window closes, misag checks whether each terminal tab's foreground program is the Claude that reported, and saves the tab with that session. On restore, a tab that runs a plain shell (not a saved command) gets `claude --resume <session>` typed at its prompt if Claude saved a conversation for it, so quitting Claude leaves you in the shell; otherwise a notice says why it was not reopened. The command is typed as soon as the shell starts, so a profile that reads input first (a passphrase prompt, an update question) or replaces the shell (`exec tmux`) takes it instead. A `claude` alias or shell function, or a profile that puts another directory holding `claude` before the wrapper on `PATH`, bypasses the wrapper; that session is not remembered, and a notice says so once it has run for a few seconds. If the wrapper cannot be written, a notice says so and terminal tabs run without it; the same goes for the `misag` shim, which is written apart from the wrapper, so either works without the other.
- Only one misag runs at a time: launching it again focuses the open window. `pnpm app:dev` builds use the identifier `io.github.ram4nd.misag.dev`, so a dev build runs next to an installed misag with its own data directory instead of being refused. Debug builds also keep their data in a `dev/` subdirectory, so even a plain `pnpm tauri dev` never touches an installed misag's data.
- Closing a tab sends SIGHUP to its process and, if it is still alive after 2 seconds, SIGKILL to its process group and to the foreground job's. Quitting misag does the same for every tab, waiting at most those 2 seconds.
- When a process exits, its tab is struck through and shows the exit code. Pressing Enter in it starts it again in the same tab; a Claude tab comes back in the session it was last in.
- Each Claude tab has its own Claude Code session. A new tab starts `claude --session-id <uuid>`. On restore it runs `claude --resume <uuid>` if Claude saved a transcript for that session, and otherwise starts again under the same id. misag passes Claude a `SessionStart` hook and a `Stop` hook through `--settings` (your own Claude config is untouched), so whenever a session starts or changes inside a tab (`/clear`, `/resume`), Claude runs `misag --claude-hook`, which records the tab's current session for the next restore; when Claude ends a turn, the same command moves the tab's flow run on (see the flows paragraphs below).
- Tabs inherit misag's environment, minus the variables a Claude Code session sets to mark itself (`CLAUDECODE`, `CLAUDE_CODE_SESSION_ID`, its messaging socket, ...) and the `MISAG_*` variables of a misag tab it was started from (whose wrapper directory is also taken off `PATH`). If misag itself was started from Claude Code, the settings Claude Code gives its commands (`GIT_EDITOR=true`, `DISABLE_UPDATES`, `CLAUDE_EFFORT`, ...) are dropped too. Your own settings such as `CLAUDE_CONFIG_DIR`, `CLAUDE_CODE_USE_BEDROCK` and `ANTHROPIC_*` are kept.
- The sidebar holds toolboxes; each one collapses from its header, and dragging a header (or Alt+Up and Alt+Down on it) moves its toolbox up or down. misag remembers which are collapsed, their order and the sidebar's width in the window's local storage, not the database; Reset sidebar on the Settings tab forgets all three. Open toolboxes share the sidebar's height equally. The Workspace box shows your workspace folder: your home directory, or the folder you pick on the Workspace settings tab, which its gear button opens (for example your projects folder). It is stored with the settings. Folders are listed when opened (at most 2000 entries each, folders first, hidden files left out); the reload button refreshes the tree, for example after new files, and keeps open folders open. Clicking a file types its path, shell-quoted if needed and followed by a space, into the active tab and switches to it. A path whose name holds control characters or a backslash is not typed (they could act as keys, or confuse fish's quoting); a notice says so. A workspace folder that has gone since you chose it shows an error in the tree but never blocks saving other settings.
- The Session history box lists the Claude conversations saved in every folder, newest first, 10 at a time (Load more shows 10 more), read from Claude's transcripts in `$CLAUDE_CONFIG_DIR/projects` (by default `~/.claude/projects`), so ones started outside misag are there too. Each shows its name from `/rename`, else Claude's title for it, else its last or first prompt, with the folder it ran in under it; conversations with no name, title or typed prompt are left out, and so are ones whose transcript names no folder (transcript lines over 1 MiB, such as large tool output, are skipped). Pinned sessions come first (newest first, on top of the 10, and only while their transcript is there and has a title and folder to show); pins are kept in the database, and a pin whose transcript Claude has deleted (see its `cleanupPeriodDays` setting) is dropped, but only once every project folder could be read: a missing projects folder, such as one looked for under the wrong `CLAUDE_CONFIG_DIR`, drops none. The list is read again with its reload button and, while the box can be seen, every 10 seconds; a transcript is read again only once it changes, and then only its new lines. Transcripts and project folders that cannot be read are counted under the list (misag prints why when started from a terminal), and tried again after a minute. A session open in a tab is marked ("this tab", or "in" and the tab's name), and clicking it shows that tab, so a conversation open in a misag tab is not resumed twice (one open elsewhere, such as in another terminal, is not detected). Otherwise clicking a session opens a new Claude tab in the session's folder that resumes it (Claude finds a session only from there).
- Flows are graphs of steps for Claude, kept in the database. A flow starts at its Start step. A Prompt step sends its text to Claude; a Manual step waits for you. Each step has outputs (short lowercase words of up to 24 characters, such as `yes, no`), and each output can lead to a next step, an earlier one included, which makes a loop. An output that leads nowhere ends the flow. The Flows tab lists the flows in the order the sidebar shows them; archived flows are hidden from the sidebar and keep their place. A flow cannot be deleted while a tab runs it.
- Flow files: a flow exports as JSON, `{"misagFlow": 1, "name": …, "graph": {"version": …, "nodes": […], "edges": […]}}`, the steps as the editor stores them (a hand-written file may leave out `version`). The Flows tab's Import… button adds a file after the other flows under its name (two flows may share a name) and opens its editor; a flow that is not ready to run is still added, and its editor says what to fix. The file dialogs are opened by the backend, so the page never names a file to read or write. Steps may leave out their position (give both `x` and `y` or neither; they are then laid out in columns from Start) and Start its output. Refused: a file from a newer misag (a higher `misagFlow`); an unknown field, so a misspelt one such as `maxruns` is not silently lost; and one that breaks the rules the editor keeps (one Start step, short lowercase outputs, at most 200 steps, and so on).
- Characters that do not show, such as zero-width spaces, bidi controls and Unicode tags, are refused in step titles and prompts (on import and in the editor), as Claude would read them unseen; the joiners and selectors that make emoji are allowed, and any left in a flow stored before are dropped from the prompts sent. Flow names may hold neither those nor control characters, and are at most 200 characters long.
- `misag flow` works with flows from a terminal: `misag flow list`, `misag flow export <id|name> [file] [--force]` (an existing file is replaced only with `--force`) and `misag flow import <file|-> [--name NAME]`, which adds the flow and lists what keeps it from running (it does not open anything). A flow imported from one of misag's tabs (where `MISAG_TAB` is set, so possibly by Claude) is marked not yet confirmed (`misag flow list` says so): its first ▶ asks you to confirm it, as its steps go to Claude unseen otherwise, and the backend refuses to start it until you have. It uses the database given with `--db`, else the one in `MISAG_DB` (set in misag's tabs), else the app's own in its data directory (see App data below; a dev build looks under both the dev and the release identifier, as `pnpm tauri dev` runs under the release one, and asks for `--db` if it finds a database under each). It refuses to create a database, and to use one at another schema than its own: only the app migrates, so after an upgrade restart the app before using it. misag's tabs, Claude tabs included, have a `misag` on their PATH that runs the misag running them (from the `cli` directory next to the database, written at every start), whatever misag is installed. Any other command (a typo such as `misag flwo`) says so and exits rather than starting the app. `misag flow help` documents the format with an example, which is how Claude learns it, and `misag --help` points there; asking Claude to run `misag flow help` first saves it guessing. The app picks up a flow added from a terminal within about 2 seconds (its poll interval).
- A flow's editor tab draws its steps on a canvas (Drawflow). Add steps with the + Prompt and + Manual step buttons above it; there is no End step, as an output that leads nowhere ends the flow (End steps in flows made by older versions still work, and still import). Delete the selected step with the Delete key or its Delete step button. Drag from an output to a step to connect them (a new connection replaces where that output went before), drag a step to move it, scroll the canvas with the mouse wheel or by dragging its empty space, zoom with Ctrl+wheel, and select one to edit its title, prompt, outputs and run limit in the side panel. Start's panel has an optional Base info text, for what Claude should know before the flow (where things are and the like), sent ahead of the run's first prompt and again with a prompt sent after the conversation was cleared; it also has "Start with /clear", so each run begins in a new conversation (see Running a flow); the canvas marks such a Start with /clear, and the toolbox shows an eraser in place of the flow icon (a run that needs attention still shows the alert). Changes are saved a moment after you make them, and when the tab closes or misag quits; a tab whose changes cannot be saved stays open and says why. The side panel lists what keeps the flow from running (Start not connected, a prompt step without text, a step Start cannot reach), or says it is ready. Start cannot be deleted. A flow has at most 200 steps, a step at most 8 outputs, and `attention` is not an output: it is reserved for Claude to ask for you.
- Running a flow: ▶ starts it in the active tab if Claude runs there (a terminal tab is checked at that moment), and types the first prompt as a paste followed by Enter. A flow whose Start clears first takes the tab, then types `/clear`, and sends the first prompt once Claude reports the clear (its SessionStart hook); it is not started while Claude is working, and is stopped if Claude leaves first or has not cleared within 30 seconds, saying why. If the page that would stop it is gone (reloaded, or it failed), the run waits for you at Start a few seconds later instead; pick its output to go on without clearing, or stop it. Until then the run shows at Start with nothing to pick. Edits in the flow's editor are saved before ▶ starts it. Each prompt asks Claude to end its reply with a last line `FLOW: <output>`. When Claude ends its turn, Claude Code runs misag's Stop hook (passed with the SessionStart hook through `--settings`), which reads that line and follows the output: the next prompt goes back to Claude as hook context and Claude carries on; a Manual step, or the end of the flow, lets Claude stop. A run whose reply has no valid `FLOW:` line, or that ends with `FLOW: attention`, waits for you as "Needs attention" with the reason, and its flow in the Flows box shows an alert icon in place of the flow icon. Answering Claude in the terminal until it ends a reply with a valid line moves it on; so does Continue (⏭ in the Flows box, or in the run bar of the flow's editor), which marks the step as running again and types Claude a reminder to go on with it and end with a `FLOW:` line, or, after the conversation was cleared, the step's prompt again; or pick an output in the run bar. Continue is not offered where it cannot help: at the 50-step limit or a step's run limit, which only picking an output passes, or when Claude Code does not report replies. A typed prompt's Enter is sent only if Claude still runs in the tab, so a terminal tab's shell never runs a flow's text. You can pick an output for a running step too, for when Claude was interrupted or crashed and no reply will come. A pick or Continue names the step it was made at, so one that arrives after the run moved on (a second click) is refused and says so rather than leaving the next step too. A tab runs one flow at a time, and its tab in the tab bar has an orange dot while its run waits for you. A run follows the flow as it was when the run started. The Flows box shows only the selected tab's run (while a page such as a flow editor is shown, the tab selected last): its flow is marked (orange while it waits for you), with ■ to stop it in place of ▶, and ▶ on the other flows is off. A run waiting at a Manual step with one output (such as `done`) shows ▶ beside ■: press it once you have done the step, and the run goes on as that output. One with several outputs lists them under its flow instead; clicking one goes on as that output, as in the run bar. The flow's editor then marks the step the run is at and shows a run bar with its status, the reason it waits, its step's outputs as the flow was when the run started, and why a pick could not go on; if that step has since been deleted from the flow, the bar says so. Whether Claude is still working shows in the tab's icon. A run whose tab is gone (its stop failed when the tab closed) marks its flow in italics in every tab, with ■ to stop it.
- Flow runs have limits and edges to know: any turn that ends while a step runs counts as its reply, including one you started by chatting with Claude, and ▶ or an output typed while Claude is busy lands in what Claude is doing. After 50 steps without you, a run waits for you. A prompt step can also have a run limit ("Run at most", shown as ≤N on the canvas), for a loop such as review, fix, review again: once the step has run that many times, the run waits for you at the step before it instead of taking it again; picking that output yourself runs it once more, as your picks are never limited. Flows with run limits, or a Start that clears or has base info, need this misag or newer; an older one refuses them. Claude Code's own limit on Stop-hook continuations (8 in a row) is raised to 51 in misag's tabs through `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`, which applies to your own Stop hooks there too. `/clear` in a running tab (other than a flow's own at its start), a failing Stop hook, and restarting misag while Claude works on a step make the run wait for you; closing its tab stops it, and so does a restart that does not bring its tab back. Prompts are sent without control characters other than newlines and tabs. A prompt longer than about 9,000 characters goes back to Claude as a "blocked" reason rather than hook context, which Claude Code may show as a hook error. Flow runs need a Claude Code that reports its last reply to Stop hooks (`last_assistant_message`); with an older one, every step waits for you, saying so.
- The Settings tab has three settings. Skip permission prompts starts Claude tabs with `--dangerously-skip-permissions` (added before the session flags above). It also reaches every `claude` started in a terminal tab through the wrapper, including one a script or tool runs (`claude -p`). A tab whose Claude runs that way, or with `--permission-mode bypassPermissions`, says so in its tooltip; a `permissions.defaultMode` in your own Claude settings is not detected. Auto memory set to Disable adds `"autoMemoryEnabled": false` to the `--settings` JSON misag passes Claude (next to misag's hooks, when there are any), in Claude tabs and terminal tabs alike; Auto (the default) leaves the key out, so your own Claude config decides. `CLAUDE_CODE_DISABLE_AUTO_MEMORY=0` in misag's environment overrides it. A change is saved right away and applies to Claude tabs started, restarted or restored afterwards, and to the next `claude` started in a terminal tab. Font size sets the size of the text in every terminal tab, 8 to 32 pixels (14 by default); it applies right away, and a size outside that range is not saved. The page reads the stored value every time it opens, so it shows what new tabs will use. The Settings and Workspace settings tabs are not saved with the other tabs. If the stored settings cannot be read, Claude tabs start cautiously (Claude asks before running tools, and auto memory is off), a notice says so, and the page shows the error and cannot change them. Without a database (see Troubleshooting) settings last only until misag quits.
- Claude is started through your login shell so it sees your usual `PATH`. Under fish, csh and other non-POSIX shells misag runs itself as `misag --exec` from the login shell, which then starts `claude`.
- App data lives in SQLite at `$XDG_DATA_HOME/io.github.ram4nd.misag/misag.db` (by default `~/.local/share/io.github.ram4nd.misag/`, WAL mode): the open tabs with each tab's directory as of the last save, the settings (one row in the `settings` table, a column per setting), app state, each Claude tab's current session, and the flows with their runs (each run keeps a copy of its flow's steps, a log of the steps it took, and each Continue with why the run waited). Tabs are saved shortly after every change and on window close, and reopened on the next launch. A saved directory that no longer exists falls back to `$HOME`. With nothing saved (or after closing every tab) the app starts with no tabs.
- Upgrading from raterm (the app's old name): on its first start misag copies raterm's database from `~/.local/share/com.tag1.raterm/raterm.db` (including what is still only in its WAL), so saved tabs, settings and flows carry over, and a notice says so; the copy is a consistent snapshot even while raterm still runs. If it fails, misag starts fresh and the notice says why and how to try again. raterm's own copy is left where it was. A tab whose Claude still runs in raterm (raterm is running) gets a new conversation instead of resuming that one, so it is not open in both apps, its flow run is stopped, and the notice says how many; reopen them from Session history once raterm has quit. The sidebar's collapsed boxes and their order reset, as the webview keeps them per app. Tabs still open in a running raterm keep reporting to raterm's database. A misag started from a raterm tab ignores that tab's `RATERM_*` variables.
- If saving is not possible, a notice above the terminals says so. A failed save is retried every few seconds. If saving fails when the window closes, the close is cancelled once with a warning; closing again quits without saving. misag never saves over tabs it could not read, including tabs a newer misag wrote.
- If a Claude tab's session hook has not reported within a minute of the tab starting, a notice says that `/clear` and `/resume` in it will not be remembered. It clears once the hook reports.
- If misag's hook logs a failure (a Stop hook failure while moving a flow run on included), a notice shows it with the path of the hook log. It clears once a session is reported again for the tab it failed for, that is when the tab next starts or changes its Claude session, or when you dismiss it.
- A dismissed notice stays hidden until something new happens.

## Troubleshooting

- **A notice says tabs are not being saved.** The database could not be opened (permissions, a newer misag's schema, no data directory). misag runs on an empty in-memory database and leaves the file alone; Claude sessions are not tracked in that mode.
- **`misag.db.broken-<time>` files.** A damaged database was moved aside and replaced; the old file is kept there for recovery and can be deleted.
- **Claude tabs do not start.** `claude` must be on your login shell's `PATH`.
- **Claude tabs do not come back in the right conversation.** Check `hook.log` next to `misag.db` (the hook-failure notice shows its path), where the session hook records its failures. Hooks must be allowed in your Claude settings, and in a folder Claude does not trust yet the hook only starts reporting after you accept Claude's trust prompt. If you use `CLAUDE_CONFIG_DIR`, set it where misag itself sees it, not only in a shell profile.
- **Going back to an older misag** after a newer one has opened the database (for example one with the workspace setting) makes the older one refuse the database and run without saving tabs. Move `misag.db` aside or upgrade again.
- **After upgrading misag**, restart it. A new version may change the database schema, and the session hook (which runs the new binary) refuses a schema it does not know until the app has been restarted and migrated it.
- **A flow run does not move on.** Select its tab and click its flow in the Flows box: the run bar of its editor says why it needs attention. A run still "Running" after Claude finished means the Stop hook did not report: check `hook.log` (failures are logged there), that hooks are allowed in your Claude settings, and that misag was restarted after an upgrade (until then the new hook cannot read the database and leaves runs alone). You can always pick an output by hand.
- **Diagnostics.** The backend prints to stderr with a `misag:` prefix; start `misag` from a terminal to see them.
